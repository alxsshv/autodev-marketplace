**Промпт для ИИ‑агента: анализ технической документации проекта и создание компактной машинной базы данных**

**Роль:** ты — оптимизатор технической информации. Твоя задача — преобразовать предоставленную техническую документацию проекта в максимально компактную структурированную базу данных **исключительно для последующего использования ИИ‑агентом**. Человеческое чтение не предполагается.

**Входные данные:** техническая документация проекта (архитектурные планы, спецификации, расчёты, требования, графики и т. д.).

**Задача:** проанализировать документацию и создать сжатую базу данных, позволяющую агенту мгновенно получать любую информацию по проекту без повторного анализа исходных материалов.

**Ключевые принципы:**
* **Максимальная компактность.** Сократи объём данных минимум на 25% относительно исходной документации.
* **Машинная ориентированность.** Формат и язык выбирай исходя из максимальной эффективности для ИИ‑агента (не для человека).
* **Самодостаточность.** База должна содержать всю критически важную информацию для работы агента.
* **Быстрота доступа.** Структура должна обеспечивать мгновенный поиск и извлечение данных.
* **Минимализм.** Оставь только то, что необходимо агенту для принятия решений и выполнения задач.

**Требования к результату:**

1. **Формат:** выбери наиболее компактный и эффективный формат для машинной обработки. Приоритеты:
    * JSON (оптимален для структурированных данных);
    * YAML (если требуется более читаемая структура);
    * структурированный plain text с чётким синтаксисом (если это даст выигрыш в компактности);
    * бинарные форматы не используй.
2. **Язык данных:** английский (все ключи, значения, описания).
3. **Обработка визуальных данных:**
    * схемы, диаграммы, планы — преобразуй в текстовое описание ключевых взаимосвязей и параметров либо в компактную JSON‑структуру;
    * удали все данные, не несущие смысловой нагрузки для агента.
4. **Структура данных:**
    * используй вложенные объекты и массивы для иерархии;
    * ключи должны быть краткими, но однозначными (например, `proj_goals`, `tech_specs`, `equip_list`);
    * для повторяющихся структур применяй массивы объектов;
    * исключай комментарии, пояснения и метаинформацию, если они не критичны.
5. **Числовые данные:** всегда указывай единицы измерения в отдельном поле или в формате `"value_unit"` (например, `"power_w": 1500` или `"length": {"value": 2.5, "unit": "m"}`).
6. **Ссылки на исходники:** для ключевых утверждений добавь поле `src` с краткой ссылкой на раздел исходной документации (например, `"src": "spec_sec_3.2"`).
7. **Кодировка:** UTF‑8.

**Алгоритм работы:**

1. Проанализируй всю документацию, выдели ключевые сущности и параметры.
2. Определи оптимальную структуру данных для данного проекта.
3. Преобразуй все данные в выбранный формат, максимально сокращая объём:
    * объединяй повторяющиеся элементы;
    * заменяй длинные описания компактными структурами;
    * удаляй избыточную информацию.
4. Проверь компактность (цель — -25% от исходного объёма).
5. Проверь полноту (все критические данные сохранены).
6. Проверь однозначность (нет двусмысленных формулировок).
7. Выведи итоговый файл.
8. Сохрани файл в каталог docs/ai/analize.md

**Формат вывода:** предоставь только итоговую базу данных в выбранном формате. **Не добавляй пояснений, комментариев или описаний формата** — агент должен сразу использовать данные.

**Пример структуры (JSON):**

```json
{
  "proj_id": "ARCH-2024-001",
  "goals": ["goal_1", "goal_2"],
  "tech_specs": {
    "load_capacity_kg": 5000,
    "operating_temp_range": {"min": -20, "max": 60, "unit": "C"},
    "power_supply_v": 220
  },
  "equip_list": [
    {
      "id": "EQUIP-001",
      "type": "pump",
      "model": "X200",
      "qty": 2,
      "specs": {"flow_rate_lps": 10, "pressure_bar": 5},
      "src": "specs_page_15"
    }
  ],

  "milestones": [
    {"phase": "design", "deadline_days": 30},
    {"phase": "construction", "deadline_days": 120}
  ]
}
```

**Критерии успеха:**
* объём данных сокращён до 75 % от начального объема или лучше;
* все критически важные параметры сохранены;
* агент может получить любую необходимую информацию за один запрос к базе;
* структура позволяет легко расширять базу при необходимости.
