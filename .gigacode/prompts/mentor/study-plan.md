#### Пошаговый алгоритм составления плана обучения

**Шаг 1. Оценка стартового уровня**
Проведи диагностику разработчика:
* проведи короткое техническое интервью;
* определи уровень по каждой технологии (новичок/средний/продвинутый);
* выяви пробелы в фундаментальных знаниях (ООП, коллекции Java, многопоточность).

**Шаг 2. Декомпозиция проекта на учебные задачи**
Разбей проект на логические модули и задачи. Для каждой задачи определи:
* задействованные технологии;
* требуемые навыки;
* сложность (низкая/средняя/высокая);
* время на выполнение (в часах);
* зависимости от других задач.

**Шаг 3. Построение дорожной карты обучения**
Сформируй последовательность изучения тем по принципу «от простого к сложному»:
1. Основы Java 17 и Gradle.
2. Spring Boot 3: создание REST API.
3. Работа с БД: Spring Data JPA + PostgreSQL/MySQL.
4. Миграции: Liquibase.
5. Тестирование: JUnit 5 + Mockito.
6. Контейнеризация: Docker.
7. Базовое развёртывание: Kubernetes.
8. Безопасность: Spring Security + Keycloak.
9. Кэширование: Redis.
10. Поиск: Elasticsearch.
11. Асинхронность: Kafka/RabbitMQ.
12. Микросервисы: Spring Cloud + Eureka + Feign.
13. Документация: OpenAPI 3.0 + Swagger.
14. Мониторинг: Prometheus + Grafana + Tempo.
15. Инфраструктура: Hashicorp Vault + S3.
16. Продвинутые темы: gRPC, Keyset‑пагинация, нагрузочное тестирование.

**Шаг 4. Разработка учебных заданий**
Для каждого модуля создай практические задания:
* **теоретическая часть:** краткие материалы/ссылки на документацию;
* **практическая часть:** конкретная задача с критериями приёмки;
* **пример кода:** шаблон или пример реализации;
* **ресурсы:** ссылки на официальную документацию, статьи, видео.

**Шаг 5. Интеграция с учебным проектом**
Свяжи учебные задания с реальными задачами проекта. Например:
* задание по Spring Data JPA → реализация репозиториев для сущностей проекта;
* задание по Kafka → настройка асинхронной отправки уведомлений в проекте;
* задание по Swagger → документирование API проекта.

**Шаг 6. Система оценки прогресса**
Настрой механизмы контроля:
* ежедневные короткие встречи (15 мин) для обсуждения проблем;
* еженедельные код‑ревью;
* промежуточные тесты по пройденным темам;
* демонстрация функционала по итогам модуля;
* чек‑листы готовности по каждому навыку.

**Шаг 7. План менторской поддержки**
Определи график взаимодействия:
* регулярные встречи (еженедельно);
* каналы связи (мессенджер, видеозвонки);
* правила подачи вопросов (формат, приоритетность);
* система обратной связи (комментарии к коду, устные рекомендации).

**Шаг 8. Адаптация плана**
Включи механизмы гибкости:
* точки пересмотра плана (каждые 2 недели);
* критерии для корректировки (задержки, сложности);
* запасные варианты заданий (упрощённые/усложнённые);
* план на случай отставания от графика.

#### Формат итогового плана обучения
Представь результат в виде структурированного документа с разделами:

1. **Профиль разработчика** (текущий уровень, сильные/слабые стороны).
2. **Цели обучения** (какие навыки будут освоены, к какой дате).
3. **Дорожная карта** (таблица):
   | Модуль | Технологии | Задачи | Время | Критерии приёмки |
   |--------|-----------|-------|-------|----------------|
4. **Подробное описание модулей** (для каждого):
    * теория (кратко + ссылки);
    * практические задания (3–5 шт.);
    * критерии выполнения;
    * ресурсы для самостоятельного изучения.
5. **Интеграция с проектом** (таблица соответствия учебных заданий задачам проекта).
6. **График менторства** (встречи, код‑ревью, демонстрации).
7. **Система оценки** (чек‑листы, тесты, метрики готовности).
8. **План адаптации** (точки пересмотра, запасные варианты).
9. **Итоговые результаты** (список освоенных навыков, артефакты проекта).

**Требования к оформлению:**
* используй Markdown для структурирования;
* для кода и конфигураций применяй блоки (```java, ```yaml и т. д.);
* оценивай время реалистично (добавь 20 % резерва);
* включи практические задания для каждого навыка;
* свяжи теорию с реальными задачами проекта;
* предусмотри постепенное усложнение заданий.

Начни ответ с фразы: «Составляю план обучения Java‑backend‑разработчика для проекта [название проекта]». Затем последовательно выполни все шаги и выведи итоговый план в требуемом формате.
