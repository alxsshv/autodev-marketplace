## Priority 1: Critical Issues (Immediate Fix Required)

### Issue 1.1: Incorrect RBAC Configuration (3 Files Affected)
**Files:**
- `docs/architecture/security/rbac.md`
- `docs/architecture/security/jwt-structure.md`
- `docs/architecture/security-strategy.md`

**Problem:** All three documents use incorrect Spring Security configuration:
```java
// WRONG - will not work!
scopesConverter.setScopeAttributeName("realm_access");
```

**Root Cause:** Keycloak JWT structure uses `realm_access.roles` (nested path), but `setScopeAttributeName()` expects the attribute name, not the full path.

**Fix:**
```java
// CORRECT
scopesConverter.setScopeAttributeName("realm_access");
scopesConverter.setAuthoritiesPrefix("ROLE_");
// Spring Security will automatically resolve realm_access.roles
```

**Alternative Fix (Explicit Path):**
```java
// More explicit approach
@Bean
public JwtAuthenticationConverter jwtAuthenticationConverter() {
    JwtAuthenticationConverter converter = new JwtAuthenticationConverter();
    
    JwtGrantedAuthoritiesConverter scopesConverter = new JwtGrantedAuthoritiesConverter();
    scopesConverter.setScopeAttributeName("realm_access");
    scopesConverter.setAuthoritiesPrefix("ROLE_");
    
    converter.setJwtGrantedAuthoritiesConverter(scopesConverter);
    return converter;
}
```

**Files to Modify:**
1. `docs/architecture/security/rbac.md` - lines ~60-65
2. `docs/architecture/security/jwt-structure.md` - lines ~110-115
3. `docs/architecture/security-strategy.md` - lines ~40-45

### Issue 3.1: Race Condition Handling for Revoked Tokens
**File:** `docs/architecture/security/revoked-tokens.md`

**Problem:** No description of race condition handling when Redis and PostgreSQL must be synchronized.

**Solution:** Add algorithm for safe synchronization:

```java
@Service
public class RevokedTokenService {
    
    @Transactional
    public void revokeToken(String token) {
        String tokenHash = sha256(token);
        long ttl = calculateTTL(token);
        
        // 1. Insert into PostgreSQL (transaction-safe)
        revokedTokenRepository.save(new RevokedToken(tokenHash, ttl));
        
        // 2. Set in Redis with TTL (idempotent)
        redisTemplate.opsForValue().set(
            "auth:blacklist:" + tokenHash, 
            true, 
            ttl, 
            TimeUnit.MILLISECONDS
        );
        
        // 3. Invalidate JWT cache
        redisTemplate.delete("auth:token:" + tokenHash);
    }
}
```

**Action:**
1. Add race condition handling algorithm
2. Document transactional guarantees
3. Add example code for safe synchronization

**Problem:** Two approaches described but not clarified as primary vs backup.

**Solution:** Clarify architecture:
```markdown
## Enabled Status Synchronization

### Primary Mechanism (MVP)
- Keycloak webhook → Auth Service
- Auth Service updates PostgreSQL
- Auth Service publishes Kafka event
- Platform Service consumes event

### Backup Mechanism (Production)
- Periodic sync job (every 10 minutes)
- Compares Keycloak vs PostgreSQL
- Fixes discrepancies
- Used only if Kafka is down

### Why Two Mechanisms?
- Kafka provides immediate synchronization
- Periodic job provides resilience against Kafka failures
- For MVP: Kafka only is sufficient
- For Production: Add periodic job as backup
```
