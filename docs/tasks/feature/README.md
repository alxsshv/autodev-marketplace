# Feature задачи для Auth Service

В этом каталоге находятся файлы задач для реализации auth-service. Имена файлов соответствуют именам веток, в которых необходимо реализовывать данные задачи.

## Структура именования

Файлы задач имеют имена по шаблону: `#<номер>-<описание-задачи>.md`

**Пример:** `#1-fix-user-entity.md`

## Согласование с GitLab

Каждой задаче соответствует GitLab issue с именем ветки `feature/#<номер>-<описание-задачи>`.

**Пример:** `feature/#1-fix-user-entity`

## Правила именования веток

- Все ветки должны начинаться с префикса `feature/`
- Имя ветки должно совпадать с именем файла задачи (без `.md`)
- Номер задачи должен соответствовать порядковому номеру в описании

## Порядок выполнения

Задачи должны выполняться в порядке возрастания номера (от #1 к #12). Это обеспечивает логическую последовательность и зависимость компонентов.

## Формат задачи

Каждая задача содержит:
- Название
- Описание (зачем нужна)
- Критерии выполнения (чек-лист)
- Ссылки на документацию
- Приоритет
- Метки

## Пример создания ветки

```bash
# Создать ветку для задачи #1
git checkout develop
git pull origin develop
git checkout -b feature/#1-fix-user-entity

# Выполнить задачу...
# Создать Pull Request
```

## Завершение задачи

После выполнения всех работ в ветке:
1. Запустить тесты
2. Создать Pull Request в ветку `develop`
3. Указать номер задачи в названии PR
4. Дождаться ревью и merge
