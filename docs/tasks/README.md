# Технические задания для Auth Service

Этот каталог содержит технические задания для разработки и улучшения auth-service.

## Порядок выполнения задач

Задачи должны выполняться в следующем порядке:

### Фаза 1: Исправление ошибок в БД (критично)
1. **AUTH-001**: Удалить таблицы ролей (auth.roles, auth.permissions, auth.role_permissions)
2. **AUTH-002**: Обновить миграции (удаление ссылок на удаленные таблицы)

### Фаза 2: Создание DTO и сущностей
3. **AUTH-003**: Создать DTO классы для API endpoints
4. **AUTH-004**: Создать мапперы для преобразования DTO и Entity

### Фаза 3: Обновление репозиториев
5. **AUTH-005**: Обновить UserRepository

### Фаза 4: Реализация сервиса и контроллера
6. **AUTH-006**: Реализовать AuthService
7. **AUTH-007**: Реализовать AuthController
8. **AUTH-008**: Настроить Spring Security

### Фаза 5: Интеграция с Redis
9. **AUTH-009**: Интегрировать Redis для кэширования токенов и пользователей

### Фаза 6: Интеграция с Keycloak
10. **AUTH-011**: Интегрировать Keycloak для получения публичных ключей

### Фаза 7: Интеграция с Kafka
11. **AUTH-010**: Интегрировать Kafka для синхронизации событий

### Фаза 8: Тестирование
12. **AUTH-012**: Написать интеграционные тесты для AuthController
13. **AUTH-013**: Написать модульные тесты для AuthService

### Фаза 9: Документация
14. **AUTH-014**: Обновить документацию

## Структура задач

Каждая задача должна выполняться в отдельной ветке с названием:
```
feature/AUTH-XXX-description
```

Где `XXX` - номер задачи, `description` - краткое описание задачи.

## Критерии готовности

Для того чтобы задача считается выполненной, должно быть выполнено:
- Все критерии выполнения, указанные в задаче
- Написаны модульные/интеграционные тесты (если применимо)
- Покрытие кода тестами >= 80%
- Добавлены Javadoc комментарии
- Написана/обновлена документация

## Вопросы и проблемы

Если у вас возникли вопросы по задаче, создайте новую задачу с меткой `question` или свяжитесь с системным аналитиком.
