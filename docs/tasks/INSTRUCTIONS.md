# Инструкция по выполнению технических заданий

## Введение

Эта инструкция описывает процесс выполнения технических заданий для auth-service.

## Общие принципы

1. **Каждая задача должна выполняться в отдельной ветке**
   - Имя ветки: `feature/AUTH-XXX-description`
   - Пример: `feature/AUTH-001-remove-roles-tables`

2. **Каждая задача должна иметь конечный результат**
   - Задачи небольшие (максимум 1-2 дня)
   - Каждая задача имеет критерии выполнения

3. **Последовательность выполнения**
   - Задачи должны выполняться в порядке, указанном в README.md
   - Начинать с критических задач (Фаза 1)

4. **Качество кода**
   - Все методы должны быть покрыты тестами
   - Покрытие кода тестами >= 80%
   - Добавлены Javadoc комментарии
   - Следовать coding standards (docs/coding-standards.md)

## Процесс выполнения задачи

### Шаг 1: Создание ветки
```bash
git checkout develop
git pull origin develop
git checkout -b feature/AUTH-XXX-description
```

### Шаг 2: Реализация задачи
- Выполнять задачу пошагово, следуя критериям выполнения
- Писать код в соответствии с coding standards
- Добавлять тесты по мере реализации

### Шаг 3: Тестирование
- Запустить модульные тесты:
  ```bash
  ./gradlew test
  ```
- Запустить интеграционные тесты:
  ```bash
  ./gradlew integrationTest
  ```

### Шаг 4: Проверка качества кода
- Проверить покрытие кода тестами:
  ```bash
  ./gradlew clean test jacocoTestReport
  ```
- Проверить форматирование кода (если используется linter)

### Шаг 5: Обновление документации
- Обновить README.md сервиса
- Добавить примеры API запросов
- Обновить OpenAPI спецификацию (если изменялись endpoints)

### Шаг 6: Создание pull request
- Отправить ветку на сервер:
  ```bash
  git push origin feature/AUTH-XXX-description
  ```
- Создать pull request в GitLab
- Указать ссылку на техническое задание
- Указать reviewers

### Шаг 7: Ревью и мерж
- Дождаться ревью от тимлида
- Внести правки по замечаниям
- Мерж ветки в develop

## Критерии готовности к мержу

Для того чтобы задача считалась выполненной и готовой к мержу, должно быть выполнено:

- [ ] Все критерии выполнения из технического задания
- [ ] Написаны модульные тесты (если применимо)
- [ ] Написаны интеграционные тесты (если применимо)
- [ ] Покрытие кода тестами >= 80%
- [ ] Добавлены Javadoc комментарии
- [ ] Написана/обновлена документация
- [ ] Все тесты проходят успешно
- [ ] Нет предупреждений от linter'а
- [ ] Код прошел ревью тимлида

## Частые проблемы и их решение

### Проблема: Падают интеграционные тесты
**Решение**: Проверить, что все контейнеры (PostgreSQL, Redis) запущены. Запустить контейнеры через Docker Compose.

### Проблема: Не компилируется код
**Решение**: Проверить версию Java (должна быть 17), проверить зависимости в build.gradle.kts.

### Проблема: Падают тесты с Redis connection error
**Решение**: Проверить, что Redis запущен и доступен по localhost:6379.

### Проблема: Падают тесты с PostgreSQL connection error
**Решение**: Проверить, что PostgreSQL запущен и доступен по localhost:5438.

## Рекомендации

1. **Выполняйте задачи по порядку**, не пропускайте задачи
2. **Пишите тесты по мере реализации**, не оставляйте их на конец
3. **Обновляйте документацию** по мере изменений
4. **Запрашивайте ревью** у тимлида после выполнения каждой задачи
5. **Документируйте проблемы** и их решения в задаче
