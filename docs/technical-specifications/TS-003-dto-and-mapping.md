## 1. Цель проекта

Создать DTO классы для обмена данными между слоями приложения и настроить маппинг между сущностями JPA и DTO.

---

## 2. Функциональные требования

### FR-1. DTO классы

**FR-1.1.** Создать класс `UserDto` для передачи данных о пользователе.

**FR-1.2.** В `UserDto` должны быть следующие поля:
- `id` — идентификатор пользователя в локальной базе
- `keycloakUserId` — идентификатор пользователя в Keycloak
- `email` — email пользователя
- `firstName` — имя пользователя
- `lastName` — фамилия пользователя
- `phone` — телефон пользователя
- `role` — роль пользователя (BUYER, SELLER, MODERATOR, ADMIN)
- `enabled` — флаг активности
- `createdAt` — дата создания
- `updatedAt` — дата обновления

**FR-1.3.** В `UserDto` добавить валидационные аннотации для всех полей.

**FR-1.4.** Создать класс `CreateUserRequest` для создания нового пользователя.

**FR-1.5.** Создать класс `UpdateUserRequest` для обновления данных пользователя. Все поля опциональны.

**FR-1.6.** Создать enum `UserRoleDto` с перечислением ролей: BUYER, SELLER, MODERATOR, ADMIN.

### FR-2. Маппер

**FR-2.1.** Создать класс `UserMapper` для преобразования между сущностью User и DTO объектами.

**FR-2.2.** Реализовать методы маппинга:
- `toDto(User user)` — преобразовать сущность в DTO
- `toEntity(CreateUserRequest request)` — преобразовать запрос в сущность
- `updateEntityFromDto(UpdateUserRequest request, User user)` — обновить сущность из DTO

**FR-2.3.** Реализовать конвертацию между UserRole и UserRoleDto.

---

## 3. Нефункциональные требования

**NFR-1.** Маппинг должен выполняться без рефлексии (compile-time generated).

**NFR-2.** DTO не должен содержать чувствительные данные (пароли, токены).

**NFR-3.** Все поля в DTO должны быть проверены валидационными аннотациями.

**NFR-4.** Код должен соответствовать конвенциям именования Java.

---

## 4. Технические требования

### 4.1. Зависимости

В `build.gradle.kts` должны быть добавлены:
- `org.mapstruct:mapstruct`
- `org.mapstruct:mapstruct-processor` (annotationProcessor)
- `org.springframework.boot:spring-boot-starter-validation`

### 4.2. Структура DTO

**UserDto** — основной объект для передачи данных о пользователе.

**CreateUserRequest** — запрос на создание пользователя (все поля обязательны кроме phone).

**UpdateUserRequest** — запрос на обновление пользователя (все поля опциональны).

**UserRoleDto** — перечисление ролей пользователей.
