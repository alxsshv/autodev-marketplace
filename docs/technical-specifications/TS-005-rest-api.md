## 1. Цель проекта

Создать REST API для управления пользователями с поддержкой валидации и обработки ошибок.

---

## 2. Функциональные требования

### FR-1. Контроллер UserController

**FR-1.1.** Создать класс `UserController` в пакете `com.autodev.auth.controller`.

**FR-1.2.** Базовый путь: `/api/v1/users`

**FR-1.3.** Реализовать эндпоинты:

**FR-1.3.1.** `GET /{id}` — получение пользователя по ID
- Возвращает 200 с DTO пользователя или 404, если не найден

**FR-1.3.2.** `GET /email/{email}` — получение пользователя по email
- Возвращает 200 с DTO пользователя или 404, если не найден

**FR-1.3.3.** `GET /` — получение всех пользователей
- Возвращает 200 со списком DTO пользователей

**FR-1.3.4.** `POST /` — создание нового пользователя
- Возвращает 201 с DTO созданного пользователя
- Возвращает 400 при ошибках валидации

**FR-1.3.5.** `PUT /{id}` — обновление данных пользователя
- Возвращает 200 с DTO обновленного пользователя
- Возвращает 404, если пользователь не найден
- Возвращает 400 при ошибках валидации

### FR-2. Валидация

**FR-2.1.** Использовать `@Valid` для валидации входных данных.

**FR-2.2.** Валидация должна проверять:
- Обязательные поля
- Длины строк
- Формат email
- Допустимые значения ролей

### FR-3. Обработка ошибок

**FR-3.1.** Создать глобальный обработчик исключений `GlobalExceptionHandler`.

**FR-3.2.** Обрабатывать исключения:
- `UserNotFoundException` — возвращать 404
- `ValidationException` — возвращать 400
- `MethodArgumentNotValidException` — возвращать 400 с деталями ошибок
- `Exception` — возвращать 500 для неизвестных ошибок

### FR-4. Документация API

**FR-4.1.** Добавить OpenAPI аннотации для всех эндпоинтов.

**FR-4.2.** Описать все HTTP статусы для каждого эндпоинта.

---

## 3. Нефункциональные требования

**NFR-1.** Все эндпоинты должны возвращать стандартные HTTP статусы.

**NFR-2.** Контроллеры должны быть задокументированы через OpenAPI.

**NFR-3.** Время отклика API — не более 500 мс для 95% запросов.

**NFR-4.** Контроллеры должны использовать Spring Security для защиты.

---

## 4. Технические требования

### 4.1. Зависимости

В `build.gradle.kts` должны быть добавлены:
- `org.springframework.boot:spring-boot-starter-web`
- `org.springframework.boot:spring-boot-starter-validation`
- `org.springdoc:springdoc-openapi-starter-webmvc-ui` (для Swagger UI)

### 4.2. Структура эндпоинтов

| Метод | Путь | Валидация | Защита |
|-------|------|-----------|--------|
| GET | `/api/v1/users/{id}` | Нет | ADMIN, BUYER, SELLER, MODERATOR |
| GET | `/api/v1/users/email/{email}` | Нет | ADMIN, BUYER, SELLER, MODERATOR |
| GET | `/api/v1/users/` | Нет | ADMIN |
| POST | `/api/v1/users/` | CreateUserRequest | ADMIN |
| PUT | `/api/v1/users/{id}` | UpdateUserRequest | ADMIN |

## 5. Критерии приемки

**HC-1.** `UserController` создан со всеми необходимыми эндпоинтами.

**HC-2.** Все эндпоинты защищены валидацией.

**HC-3.** Глобальный обработчик исключений создан.

**HC-4.** Все эндпоинты возвращают правильные HTTP статусы.

**HC-5.** Проект компилируется без ошибок: `./gradlew build`.
