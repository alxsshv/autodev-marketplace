## 1. Цель проекта

Реализовать сервисный слой для управления пользователями с поддержкой кэширования, транзакций и логирования.

---

## 2. Функциональные требования

### FR-1. Интерфейс UserService

**FR-1.1.** Создать интерфейс `UserService` в пакете `com.autodev.auth.service`.

**FR-1.2.** Реализовать методы:
- `findByKeycloakUserId(String keycloakUserId)` — найти пользователя по Keycloak ID
- `findByEmail(String email)` — найти пользователя по email
- `createUser(CreateUserRequest request)` — создать нового пользователя
- `updateUser(Long id, UpdateUserRequest request)` — обновить данные пользователя
- `getAllUsers()` — получить всех пользователей

**FR-1.3.** Все методы должны возвращать DTO объекты или списки DTO объектов.

### FR-2. Кэширование

**FR-2.1.** Настроить кэширование для методов поиска с помощью `@Cacheable`.

**FR-2.2.** Время жизни кэша — 10 минут.

**FR-2.3.** Использовать Redis для хранения кэша.

### FR-3. Транзакции

**FR-3.1.** Настроить транзакции для методов записи с помощью `@Transactional`.

**FR-3.2.** Все операции создания и обновления должны быть транзакционными.

### FR-4. Конвертация

**FR-4.1.** Реализовать конвертацию между сущностями и DTO с помощью `UserMapper`.

**FR-4.2.** Установить роль по умолчанию BUYER, если не указана.

**FR-4.3.** Установить `enabled = true`, если не указано иное.

---

## 3. Нефункциональные требования

**NFR-1.** Операции поиска должны использовать кэш Redis.

**NFR-2.** Все операции записи должны быть транзакционными.

**NFR-3.** Все операции должны логироваться через SLF4J.

**NFR-4.** Корректная обработка исключений и возврат правильных HTTP статусов.

---

## 4. Технические требования

### 4.1. Зависимости

В `build.gradle.kts` должны быть добавлены:
- `org.springframework.boot:spring-boot-starter-data-redis`
- `org.springframework.boot:spring-boot-starter-cache`
- `org.springframework.kafka:spring-kafka` (если требуется отправка событий)

### 4.2. Конфигурация кэширования

**Кэш users:**
- Имя кэша: `users`
- Время жизни: 10 минут
- Ключ: `keycloakUserId` или `email` пользователя

**Конфигурация очистки:**
- Очищать кэш при обновлении данных пользователя.

### 4.3. Конфигурация транзакций

**Аннотация `@Transactional`:**
- Применять ко всем методам записи (create, update)

---

## 5. Критерии приемки

**HC-1.** Интерфейс `UserService` создан со всеми необходимыми методами.

**HC-2.** Методы поиска кэшируются с помощью `@Cacheable`.

**HC-3.** Методы записи транзакционны с помощью `@Transactional`.

**HC-4.** Кэш очищается при обновлении данных.

**HC-5.** Созданы кастомные исключения для обработки ошибок.

**HC-6.** Проект компилируется без ошибок: `./gradlew build`.

---

## 6. Примечания для разработчика

- Разработчик должен сам решить, как реализовать кэширование и транзакции.
- Можно использовать любые паттерны проектирования для сервисного слоя.
- Логирование должно быть информативным и полезным для отладки.
