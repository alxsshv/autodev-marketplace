## 1. Цель проекта

Настроить интеграцию с Apache Kafka для асинхронной коммуникации между микросервисами через события жизненного цикла пользователей.

---

## 2. Функциональные требования

### FR-1. События пользователей

**FR-1.1.** Создать класс `UserCreatedEvent` для события создания пользователя.

**FR-1.2.** Создать класс `UserUpdatedEvent` для события обновления пользователя.

**FR-1.3.** Создать класс `UserDeletedEvent` для события удаления пользователя.

**FR-1.4.** Каждое событие должно содержать:
- `eventId` — уникальный идентификатор события
- `keycloakUserId` — ID пользователя в Keycloak
- `email` — email пользователя
- `firstName`, `lastName`, `phone` — данные пользователя
- `role` — роль пользователя
- `enabled` — флаг активности
- Временные метки создания/изменения/удаления

### FR-2. Kafka Producer

**FR-2.1.** Создать класс `UserEventProducer` для отправки событий.

**FR-2.2.** Отправлять событие `UserCreatedEvent` при создании пользователя.

**FR-2.3.** Отправлять событие `UserUpdatedEvent` при обновлении пользователя.

**FR-2.4.** Отправлять событие `UserDeletedEvent` при удалении пользователя.

**FR-2.5.** Использовать CompletableFuture для асинхронной отправки событий.

### FR-3. Kafka Consumer

**FR-3.1.** Создать класс `UserEventConsumer` для получения событий.

**FR-3.2.** Настроить слушателя для топиков `user-created`, `user-updated`, `user-deleted`.

**FR-3.3.** Обрабатывать полученные события в методах-слушателях.

### FR-4. Интеграция с сервисом

**FR-4.1.** В `UserServiceImpl` вызывать `UserEventProducer` при создании и обновлении пользователя.

**FR-4.2.** Событие должно отправляться только после успешного сохранения в базу данных.

---

## 3. Нефункциональные требования

**NFR-1.** Все события должны быть надежно доставлены (acknowledgments).

**NFR-2.** Система должна поддерживать рост количества событий.

**NFR-3.** Все события должны логироваться через SLF4J.

**NFR-4.** Отправка события не должна блокировать основной поток выполнения.

---

## 4. Технические требования

### 4.1. Зависимости

В `build.gradle.kts` должны быть добавлены:
- `org.springframework.kafka:spring-kafka`
- `org.springframework.boot:spring-boot-starter-data-redis` (для кэширования)

### 4.2. Конфигурация Kafka

**Базовый сервер:** `kafka:9092` (имя сервиса в Docker)

**Producer:**
- Key serializer: `StringSerializer`
- Value serializer: `JsonSerializer`

**Consumer:**
- Group ID: `auth-service-group`
- Key deserializer: `StringDeserializer`
- Value deserializer: `JsonDeserializer`

### 4.3. Топики

**user-created** — события создания пользователей

**user-updated** — события обновления пользователей

**user-deleted** — события удаления пользователей

---

## 5. Критерии приемки

**HC-1.** Классы событий созданы (UserCreatedEvent, UserUpdatedEvent, UserDeletedEvent).

**HC-2.** Kafka Producer создан и отправляет события.

**HC-3.** Kafka Consumer создан и получает события.

**HC-4.** Интеграция с UserService реализована.

**HC-5.** Проект компилируется без ошибок: `./gradlew build`.

---

## 6. Примечания для разработчика

- Разработчик может выбрать любую стратегию доставки событий (at-least-once, at-most-once, exactly-once).
- Структура пакетов внутри `event/`, `producer/`, `consumer/` может быть изменена по усмотрению разработчика.
- Для интеграционного тестирования можно использовать Testcontainers с Kafka.
