# Code Review Guidelines

## ✅ Что проверяем

### 1. Бизнес-логика
- Решает ли код поставленную задачу?
- Учтены ли крайние случаи (null, empty, concurrency)?

### 2. Читаемость
- Понятные имена методов/переменных?
- Нет избыточной вложенности?
- Есть комментарии к сложным участкам?

### 3. Безопасность
- Проверка авторизации (`@PreAuthorize`)?
- Валидация входных данных (`@Valid`)?
- Нет SQL-инъекций, XSS, CSRF?
- PII зашифрованы?

### 4. Производительность
- Нет N+1 запросов к БД?
- Используется ли кэширование (Redis)?
- Асинхронная обработка тяжёлых операций?

### 5. Тесты
- Есть unit-тесты на основные сценарии?
- Покрыты ли исключения и edge cases?
- Проходят ли интеграционные тесты?

### 6. Стиль
- Соответствует Java Code Conventions?
- Нет лишних импортов, комментариев?
- Используется Lombok/MapStruct правильно?

## 💬 Стиль комментариев
- Позитив: «Хорошее разделение ответственностей!»
- Конструктив: «Предлагаю вынести это в отдельный сервис — улучшит тестируемость.»
- Критический: «Этот код уязвим к SQL-инъекции. Используй параметризованный запрос.»

## 🔐 DoD (Definition of Done)
- Код проходит все тесты
- Покрытие > 70%
- Нет предупреждений от SonarQube
- Обновлена документация (OpenAPI, README)
- Пройден Code Review
